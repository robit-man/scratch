Room security + persistence

The URL fragment is the key. The value after # is never included in HTTP requests. This page hashes it to create a rendezvous room name and separately derives an AES-256-GCM application key from the original fragment.

Network payloads are therefore protected by WebRTC transport encryption and application-layer encryption. File names, scratch text, asset metadata and file bytes are encrypted; signaling sees only a hash-derived room identifier and transport metadata.

Anyone with the complete link can read and modify the room. Use the generated high-entropy room URLs rather than short human passwords. This is capability-based access, not an account system.

No central archive exists. Each browser keeps an encrypted local cache. A new browser can recover the current state only while at least one peer that already has that state is online. Large files are transferred peer-to-peer and are not uploaded to this host.
